# 独立票据页面与飞机可见性验收

## 已复现根因

起飞后 #flight 显示、#planner 隐藏，但 body[data-hangke-scene] 仍是 ready。其 CSS 隐藏整个 #map，飞机 DOM overlay 已存在却继承 visibility:hidden。计时器独立于地图所以仍正常运行。不是模型缺失或进度重置。

修复前 Windows 断言失败：scene=ready，mapVisibility=hidden，plane=true，planeVisibility=hidden。修复后同一路径通过：scene=flying，地图和飞机 visibility=visible。before.json/after.json 为实测数据。

## 修复

- 由实际显示页面统一同步场景；起飞、暂停恢复、关闭重开、历史和降落不再沿用过期的预飞行背景。
- 出票和取票/值机采用同一深色独立背景；隐藏整个地图及控件，不保留地名、机场、雷达。移除票据布局触发隐藏地图相机调整的调用。
- 保留连续打印、撕票根、条码/二维码及草稿与真实航班边界。票据前后实测560×336 CSS像素，字段与条码像素相同；窄窗口统一缩放。
- 路线视图为底部计时/操作预留构图空间，避免起飞初期飞机与计时器重叠。焦点恢复清零padding；不修改位置、bearing或进度。

## 实测结果

- npm run build 通过；npm test 37/37；git diff --check 通过。
- 最终 exe 内嵌 JS/CSS 哈希与构建产物一致，exe 哈希见 manifest.json。
- Windows 完整选座、客舱退场、打印、取票、拖拽与键盘撕票、准备、起飞、焦点/路线切换通过。地图与飞机恢复可见，白色渐隐尾迹沿已有航迹绘制。
- 末排、88座、纸张前后尺寸/数据、窄窗口、打印中缩放、返回/Esc取消、重复点击、减少动态通过。
- 真实 Windows 最小化恢复、暂停、关闭进程后重开、同一航班恢复及历史持久化通过。
- 自动降落以隔离测试档案的临近截止时间验证一次性落库；未声称等待完整30分钟或验证物理睡眠。

## 人工验收

当前未发现阻塞问题；视觉与转场自然度仍请人工确认。尾迹只表示已经飞过的路径，刚起飞时会很短，缩小至完整航线视图时更不明显，不伪造额外飞行距离。没有commit、merge或替换正式版。
